## Что это

Веб-приложение для старосты учебной группы: расписание с чётностью недель, отметка
посещаемости, live-список «кто идёт», статистика, объявления, дедлайны, домашние задания.
Работает как PWA — ставится на телефон.

Группа: **05-605**, «Математика и компьютерные науки» / «Наука о данных».

## Публичная ссылка

Туннель через serveo (аккаунт у пользователя, ключ зарегистрирован):

```powershell
powershell -ExecutionPolicy Bypass -File scripts/tunnel-serveo.ps1
```

→ https://gruppa-pmi21.serveousercontent.com

Важно:
- serveo рвёт туннель каждые ~30 минут, скрипт переподключается сам, адрес не меняется
- цель указывать `127.0.0.1`, не `localhost` (иначе IPv6 и 502)
- Cloudflare-туннели на этой сети **не работают** (`Register tunnel error: context deadline exceeded`)
- бесплатный serveo показывает посетителям страницу «Continue to Site»

## Проверка

Smoke-тест поднимает свой сервер на временной базе — реальную группу не трогает.
Для скриншотов нужна сессия: `$env:SHOT_COOKIE = "<token>"` (см. ниже, как создать).

## Что сделано (по коммитам)

- `server/` — Express 5 + `node:sqlite` (без native-сборки)
- расписание: произвольное время, диапазоны дат, чёт/нечет от начала семестра (`semester_start`)
- подгруппы (Маклецов / Давлетов), выбор в профиле, фильтрация пар
- отметки: одна пара / весь день, статусы иду-опоздаю-не иду-уваж
- статистика, «кто идёт» через SSE, объявления, дедлайны с живым отсчётом
- ДЗ: привязка к паре, добавление любым студентом, «сделал» у каждого
- мультигрупповость: любой может создать свою группу (вкладка «Новая группа»)
- auth: scrypt, HttpOnly-сессии, роли, лимит попыток входа, пароль от 8 символов
- PWA: манифест, service worker, web-push (VAPID-ключи в базе, напоминания за 15 минут)

## Известные ограничения

1. **Код группы = её номер** (`05-605`) — любой, кто знает номер, может вступить.
   Лечится: случайный код вместо номера.
2. **Сервер живёт на ноутбуке** — пока он выключен, сайта нет.
3. **serveo видит трафик** (TLS заканчивается у них).
4. **Нет бэкапов** базы.
5. **Данные на диске не зашифрованы** (пароли — хешированы).

## Что дальше (приоритет)

1. **Хостинг.** Пользователь хочет постоянный. Oracle отпал (карта РФ не проходит).
   Осталось выбрать:
   - **Render + Neon** — 0 ₽ без карты, но нужен переезд БД на Postgres (~час) и засыпание
   - **Российский VPS** ~200–300 ₽/мес (Timeweb, Aeza, Beget) — SQLite остаётся, 15 минут настройки
2. Случайный код группы (снимает риск №1).
3. Бэкап базы по cron после переезда.

## Как создать сессию для проверки

```powershell
node --input-type=module -e "const {db}=await import('./server/db.js'); const {randomBytes}=await import('node:crypto'); const u=db.prepare(\"SELECT id FROM users WHERE role='starosta'\").get(); const t=randomBytes(32).toString('hex'); db.prepare('INSERT INTO sessions (token,user_id,created_at,expires_at) VALUES (?,?,?,?)').run(t,u.id,new Date().toISOString(),new Date(Date.now()+3600e3).toISOString()); process.stdout.write(t)"
```

## Стиль работы, который зашёл пользователю

- Сначала проверить факты в коде/живьём, потом утверждать
- Скриншоты после изменений в UI, проверка глазами
- Коротко объяснять «почему», а не только «что»
- Не выдумывать: если не проверил — так и сказать
